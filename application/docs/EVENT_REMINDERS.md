# Напоминания о мероприятии

Laravel Scheduler каждую минуту запускает `events:remind`. Команда выбирает
оплаченные заказы с действующими билетами без `refund_required`, если мероприятие
опубликовано и начнётся в интервале `(сейчас, сейчас + 24 часа]`.
Для каждого заказа в очередь `notifications` ставится `SendEventReminder`.

Это не обещание доставки ровно за 24 часа: учитывается минутный интервал проверки
и время обработки очереди. Купившие билет позже тоже получают напоминание до начала.
Если приложение было выключено весь оставшийся период до начала, письмо не отправляется.

Обработчик повторно читает мероприятие и заказ под блокировками в порядке
«мероприятие → заказ», как оплата, отмена и check-in. Неоплаченные заказы,
отменённые/завершённые/начавшиеся мероприятия, использованные/отменённые билеты
и билеты с необходимостью возврата пропускаются.
Если в заказе несколько билетов, письмо содержит только оставшиеся действующие.

Письмо содержит название, дату и время с часовым поясом, место и адрес,
номер заказа, типы и номера действующих билетов. Данные времени берутся из приложения
(часовой пояс выводится явно); часовой пояс пользователя пока отдельно не хранится.

## Защита от повторов и ошибки

- `ShouldBeUnique` не допускает постановку одинаковых заданий для одного заказа
  при очередных запусках команды. Используется общий Laravel Cache, срок блокировки — час.
- После успешной отправки в `orders.event_reminder_sent_at` сохраняется время.
  Повторное выполнение задания проверяет эту отметку под блокировкой.
- На один заказ отправляется одно напоминание. При нескольких заказах покупателя
  придёт отдельное письмо на каждый. После изменения даты уже отправленное напоминание
  автоматически не повторяется.
- При ошибке SMTP отметка не записывается, очередь делает до трёх попыток
  с задержками 10 и 60 секунд. Необработанные сбои видны через `queue:failed`.
  Пока мероприятие впереди, Scheduler может снова поставить задание после снятия
  блокировки уникальности.
- Сбой между фактической отправкой SMTP и сохранением отметки в БД может вызвать
  повторное письмо; гарантировать строго одну доставку средствами SMTP нельзя.

## Файлы

- `app/Console/Commands/SendEventReminders.php` — отбор заказов и постановка в очередь.
- `app/Jobs/SendEventReminder.php` — повторная проверка и отправка.
- `app/Mail/EventReminder.php`, `resources/views/email/event-reminder.blade.php` — письмо.
- `routes/console.php` — расписание каждую минуту.
- `2026_10_20_130000_add_event_reminder_to_orders.php` — отметка отправки.

## Проверка локально

1. Создать опубликованное мероприятие с началом, например, через два часа
   и оплатить заказ с билетом. Существующие мероприятия переносить для проверки не нужно.
2. Дождаться минутного запуска Scheduler или вызвать:

```powershell
docker exec events-project-php-1 php artisan events:remind
```

3. Открыть [MailHog](http://localhost:8025) и найти письмо «Напоминание о мероприятии».
4. Повторить команду: после успешной отправки новое письмо для заказа не появится.

Контейнеры `scheduler` и `queue` должны работать. Для просмотра расписания:

```powershell
docker exec events-project-php-1 php artisan schedule:list
```
